## 4. 关键设计说明 (5 个必答点的实现)

### 4.1 Q1: ChatWindow 单例 → SessionMode 全局单例

`SessionModeState` 是 static class, 单例语义. 通过 `EditorPrefs` 全项目共享 (不做 per-project hash, 跨项目通用).

### 4.2 Q3: Silent buffer 只存里程碑事件 (已合并后)

**没有额外过滤**——因为 v1.8.5 + v1.8.6 已经在 EmitEvent 上游把 StreamToken/ReasoningToken **累积到 flush 事件里再 emit**, 上游本来就不会 emit 逐 token 事件. 所以 `_silentBuffer` 里存的都是里程碑级 (ContentFlush 后的 StreamToken, ReasoningFlush 后的 ReasoningToken, ToolCall*, LoopCompleted, StateChanged, ErrorEvent).

### 4.3 Q4: 手动切出 flush 走事件通道

`OnSessionModeChanged(Batched)` 调 `FlushSilentBuffer` → 内部逐个 `AsyncHelper.RunOnMainThread` marshal 到主线程. 保证事件语义链路一致 (StateChanged / ToolCallStarted 都被订阅方看到, 只是一波集中发出).

### 4.4 Q5: reasoning 分块 flush = \n\n 或 200 字任一先到 + Done 强制

`AppendReasoningToken` 每次 append 后调 `ShouldFlushPendingReasoning`:
- 长度 ≥ 200 字 → true
- 或 `Contains("\n\n")` → true

`FlushAccumulatedContentIfAny` 在 Done/Error 时无条件 flush 剩余 reasoning + content.

**性能敏感说明**: `ShouldFlushPendingReasoning` 里 `_pendingStreamReasoning.ToString()` 每次都分配, reasoning append 频率低于 content 认为可接受. 未来若成为热点可改增量扫描.
