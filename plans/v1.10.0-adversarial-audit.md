### C.1 测试覆盖与发现

**完整详情**: [`plans/v1.10.0/smoke-test-findings.md`](v1.10.0/smoke-test-findings.md)

### C.2 新识别的系统性问题

#### C.2.1 提供商兼容性裂痕 (Bug E/K)

**根因**: GLM (零一万物) 将嵌套对象/数组/数字序列化为 JSON **字符串**，与 OpenAI/Anthropic 不一致。

**影响范围**: 所有复合参数工具

**修复措施 (v1.10.2)**:
- Validator 层: 字符串到类型的 coercion (原地 JToken.Parse + 重写)
- Handler 层: 21 处 `.Value<T>()` 迁移到 `TryCoerce*` helpers
- Warning 日志: 记录 provider 不兼容行为

**审计影响**: **新增审计维度 — 提供商兼容性**，未来每新增 provider 需验证参数序列化行为。

#### C.2.2 Unity API Drift 反射脆弱性 (Bug S, R4 复现)

**根因**: Unity 2022.2+ 将 `MemoryProfiler.TakeSnapshot` 从 Experimental → 正式命名空间，旧类型存在但 `GetMethods()` 返回空。

**R4 根因回顾** (v1.7.27): 反射类型未在 ReferenceAssembly 里 → v1.8.0 G02 双开关修复。

**v1.10.0 复现**: G04 MemoryProfiler 用纯反射，但只验证了新 namespace (package 安装后)，未测试旧 namespace 的 `GetMethods()` 可用性。

**修复措施 (v1.10.3)**:
- 4-tier reflection fallback chain (新 namespace → 新+assembly qualifier → 旧 Experimental → 旧+qualifier)
- `GetMethods()` 非空验证 (不能只检查类型存在)

**审计影响**: **R4 根因未完全消除**，反射探测流程需加强 — 类型存在 ≠ 方法可用。

#### C.2.3 响应压缩漏洞 (Bug C 升级为 P0)

**场景**: W8 测试中，LLM 错误调用 `profiler.list_stats` 无 filter，返回 822K chars / ~20M tokens。

**根因**: `ToolResultCompressor` 有启发式压缩，但无硬上限。

**影响**: 几乎耗尽上下文窗口 (假设 200K tokens)，后续对话无法进行。

**v1.11 计划**:
- 高容量工具 (profiler / memory_profiler / scene_analysis) 加 5000 chars 硬上限
- 必填 filter 参数

**审计影响**: **新增审计维度 — 响应容量控制**，工具返回值需分级限制。

#### C.2.4 确认面板流程倒置 (Bug P)

**Bug**: `ToolCallDispatcher` 在参数校验前触发确认 UI → 用户批准后才发现参数错误。

**正确流程**: Validate → Confirm → Execute

**影响**: 用户体验差，安全流程形同虚设。

**v1.11 修复**: 将 `ToolRiskPolicy.Evaluate` 移到 `ToolParameterValidator.Validate` 之后。

**审计影响**: **UX 流程健壮性检查遗漏** — 初始审计未覆盖 UI 交互时序。

#### C.2.5 Per-Action RiskLevel 缺失 (Bug Q)

**Bug**: `manage_prefs` 整个工具 `RiskLevel=High` → 只读 action (get/has) 也弹确认。

**理想**: 按 action 分级 (get/has=ReadOnly, set/delete=High, delete_all=Destructive)

**v1.11 修复**: ToolRiskPolicy 支持 per-action RiskLevel 覆盖。

**审计影响**: **RiskLevel 粒度不足** — 工具级 RiskLevel 太粗，需 action 级。
