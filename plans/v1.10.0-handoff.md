### 2.4 主线程性能问题 — 未定论

[`perf-issue-editor-hang-during-agent-run-summary.md`](perf-issue-editor-hang-during-agent-run-summary.md) 记录:

- **现象**: 流式期 552-829 ms/帧 (稳态 5.79 ms/帧 = 172 FPS)
- **已收敛**: GC 从 7.9 MB → 410 KB (19× 改善), UI 4 个定时动画全关
- **未定论根因**: 假设 A (UI 事件密集) / B (SynchronizationContext 队列) / C (UpdateSceneIfNeeded 项目本身重), 三个假设**均未做决定性验证**
- **规避手段**: SessionMode Silent 模式让用户手动切"冻结 UI" (v1.8.8~1.8.10 已交付)

**v1.10.0 决策**:
- 选项 A: **不再深挖根因**, Silent 模式作为长期 workaround, 优先做工具增强
- 选项 B: 优先花 1-2 天验证假设 A/B/C 之一 (推荐 `ConfigureAwait(false)` 试验), 结论落地为普适性改进
- **建议 A** — 主线程问题在有 Silent 模式的前提下不是 blocker; 工具增强能带来更直接的能力扩展

### 2.5 G03 FrameDebugger 真实数据未验证

主线程问题不解决 → GameView 不渲染 → FrameDebugger 采不到 event → G03 未回头验证. **但 Silent 模式下用户手动切 Silent 后主线程释放, GameView 会渲染** — 意味着 Silent 模式**间接解决** G03 验证障碍. 建议 v1.10.0 第一周找机会在 Silent 模式 + Play Mode 场景下补验证.

### 2.6 G10 SRP 真实环境未验证

Megacity Metro 是 URP 项目, 理论上是**天然验证场**. 建议 v1.10.0 首日先在这个项目里跑 `volume_list / volume_get / volume_set` 全流程, 拿到真实数据后如有 bug 修 patch, 无 bug 关闭 HANDOFF §3.2 遗留.

### 3.4 反射探测 (G04 前置任务)

**执行方式**: 在 AgentCore Chat 里 `execute_code` 运行以下, 拿到输出保存到 `plans/v1.10.0/g04-reflection-probe.md`:

```csharp
var sb = new System.Text.StringBuilder();
string[] typeNames = new string[] {
    "Unity.MemoryProfiler.Editor.CachedSnapshot, Unity.MemoryProfiler.Editor",
    "Unity.MemoryProfiler.Editor.MemoryProfilerModuleBridge, Unity.MemoryProfiler.Editor",
    "UnityEngine.Profiling.Memory.Experimental.MemoryProfiler, UnityEngine.Profiling.MemoryProfiler.Module",
    "UnityEditor.Profiling.Memory.Experimental.PackedMemorySnapshot, UnityEditor.Profiling.MemoryProfiler.Module",
};
var flags = System.Reflection.BindingFlags.Public | System.Reflection.BindingFlags.NonPublic | System.Reflection.BindingFlags.Static | System.Reflection.BindingFlags.Instance | System.Reflection.BindingFlags.DeclaredOnly;
foreach (var tn in typeNames) {
    var t = System.Type.GetType(tn);
    if (t == null) { sb.AppendLine("NULL: " + tn); continue; }
    sb.AppendLine("=========== " + t.FullName + " ===========");
    foreach (var mi in t.GetMethods(flags)) if (!mi.IsSpecialName) sb.AppendLine("  " + mi.Name + "(" + mi.GetParameters().Length + " args) -> " + mi.ReturnType.Name);
    foreach (var pi in t.GetProperties(flags)) sb.AppendLine("  prop " + pi.PropertyType.Name + " " + pi.Name);
}
UnityEngine.Debug.Log(sb.ToString());
sb.ToString()
```

## 4. 一致性原则 (v1.10.0 开发过程中的红线)

### 4.1 一致性四原则

1. **规划优先**: 动手前一次 grep 现有代码, 避免"发明轮子" (v1.7.29 教训)
2. **对抗性校验**: 每写完一个 action 后跑 [`plans/adversarial-coverage-audit.md`](adversarial-coverage-audit.md) 的 Mutating-side 检查 (Undo 是否入栈 / write API 是否走 ToolHelpers)
3. **反射不盲写**: 走两阶段模式 (磁盘 dnfile 找 assembly + Editor 运行时 GetMembers). Cache resolved reflection 但保留 error state
4. **可选 package 隔离**: asmdef `versionDefines` + fallback stub. **不**加 references 硬依赖

### 4.2 ADR-17 极简哲学要求

按 [`adr-17-minimalism.md`](adr-17-minimalism.md) §1 五条规则, v1.10.0 新增 action 时:
- **默认最优, 不问用户**: e.g. `analyze_memory_snapshot.top_n=50` 写死不给 UI 选项
- **术语必须白话**: e.g. schema 用 `group_by="type"` 不用 `groupByStrategyEnum`
- **不加 UI 卡片**: v1.10.0 全部是 tool 深化, 不涉及 Settings 页面新卡片

### 4.3 L10n 规则

- **工具描述** (AgentToolAttribute description): 保留**英文**, 因为它是给 LLM 看的, 影响 tool selection 准确率
- **用户可见的错误消息 / dialog 文本**: 走 `Loc.Tr(key, fallback_zh)` (fallback 是中文, 与已推 v1.9.x 风格一致)
- **只读的调试文本 / SOUL prompt / Bootstrap 内容**: 保留原文, 不本地化

### 4.4 SessionMode Silent 兼容

新增长时任务 (e.g. G12 lightmap async bake, G04 memory snapshot 抓取几十秒) **必须**:
- 在 Silent 模式下也能跑
- 通过 [`AgentLoop.Events.cs`](../Editor/Core/AgentLoop.Events.cs) 里 `IsUserInteractionEvent` 白名单允许状态标签正常更新
- 建议: 长任务开始/结束都 emit `StateChanged` 事件, 依赖白名单直通; 中间进度更新可以用 Silent buffer

## 6. 已知陷阱 (对下一 session 的警告)

### 6.1 v1.7.29 教训 — "回答不能→事后发现存在"

新增 action 前**先 grep 现有 47 工具**, 不要凭直觉判断"这个能力还没有". [`tools/tool-inventory.cjs`](../tools/tool-inventory.cjs) 是唯一真源, 每次 v1.10.0 阶段开工前跑一次.

### 6.2 反射盲写 (v1.7.26/27 + v1.8.0 G02 双开关翻车)

G04 MemoryProfiler 反射 `Unity.MemoryProfiler.Editor.CachedSnapshot` internal API **必须**先做两阶段探测:
- 阶段 1: 磁盘 dnfile 找 assembly + 类型存在性
- 阶段 2: Editor 运行时 GetMembers dump 完整签名到 markdown

**不要直接**在 tool handler 里写 `Type.GetType(...).GetMethod("TakeSnapshot")` — 该 method 可能是 overload, 需 GetMethods 遍历 + 参数类型匹配.

### 6.3 Undo 契约

G08 EditorPrefs / PlayerPrefs 是**不可逆**操作 (删除后无法通过 Ctrl+Z 恢复), 必须:
- 加入 [`AgentLoop.Runner.cs`](../Editor/Core/AgentLoop.Runner.cs) 里的 intentionally non-undoable 白名单
- Tool description 明确写 "This is destructive. Use trust prompts."
- 走 High risk / DestructiveWrite capability 标注, 强制弹确认框

### 6.4 SessionMode Silent 事件白名单

新增长任务的进度事件如果**不**在 [`AgentLoop.Events.cs`](../Editor/Core/AgentLoop.Events.cs) 的 `IsUserInteractionEvent` 白名单里, Silent 模式下会被 buffer 而不马上显示. **决策**: G04/G12 类长任务的**开始/结束**用 `StateChanged` (已在白名单), **中间进度**用 `ToolCallProgress` (需要新增到白名单, 或走 buffer 定期批量 emit).

### 6.5 L10n 覆盖 vs 工具描述

新 action 的 `AgentToolAttribute.Description` **保持英文**, 否则 LLM tool selection 准确率下降 (LLM 训练语料以英文为主). 但 tool handler **返回的错误消息** 走 `Loc.Tr` (那是给用户看的).
