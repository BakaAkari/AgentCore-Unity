## 图例
- **根因**: `NO_TOOL` (完全没) / `SHALLOW` (有工具但覆盖不全) / `DISCOVER` (工具在但 agent 找不到) / `NOT_A_GAP` (execute_code 已够)
- **投入**: 半天/1 天/2-3 天/大 (>3 天)
- **风险**: 反射漂移 / package 版本 / API 复杂度 / 兼容破坏
- **建议**: `INCLUDE` (建议进 v1.9.0) / `DEFER` (顺延) / `SKIP` (排除, 附理由)

## v1.9.0 建议范围

**A. 最小可行 (半周)** — 3 项, 快速验证 v1.9.0 主题:
- G04 MemoryProfiler (2-3 天)
- G06 Selection 深化 (1 天)
- G07 CompilationPipeline (半天)
- **总计**: ~4 天, 覆盖 "内存排查 + 常用工作流"

**B. 平衡 (一周)** — 6 项, v1.9.0 主体:
- 上面 3 项 +
- G05 Physics 深化 (1 天)
- G08 EditorPrefs (1 天)
- G09 SceneView 相机 (半天)
- **总计**: ~7 天

**C. 全面 (两周)** — 9 项, 覆盖所有 P1 高价值:
- 上面 6 项 +
- G12 Lightmapping GI 深度 (1 天)
- G14 Presets (1 天)
- G11 OcclusionCulling (1 天)
- **总计**: ~10-12 天

**D. 你想插入 Megacity Metro 特化**: 因为你自己项目用 Netcode, 可以把 P2-c 从 DEFER 升到 INCLUDE. 但这会引入可选 package 依赖 (跟 G10 SRP core 同套 Version Defines 模式), 且 Netcode API 相对复杂. **建议**: v1.9.0 先不做, 等 P1 收敛后 v1.10.0 首选做.

## 主线程性能问题 (v1.8.0 遗留)

独立于工具覆盖面, [`plans/perf-issue-agent-streaming-blocks-editor.md`](perf-issue-agent-streaming-blocks-editor.md) 记录的 228ms/帧 主线程阻塞是**用户可感知的最严重问题**. 建议:

- **纳入 v1.9.0 作为前置修复项**, 优先级高于任何 P1 覆盖新增
- 三条候选方案文档已就绪 (异步 flush / 累积 flush / 静默+状态栏)
- 投入估算: 1-2 天 (取决于选哪条方案)
- 修完后 G03 event 采集才能真验证 (副产物)

## 决策后我的执行方式

- 每完成一项发一个 patch tarball (v1.8.2 / v1.8.3 / ..., 达到 v1.9.0 范围后再 bump minor 到 v1.9.0)
- 每份 tarball 附一句"改了什么, 请测什么", 你人工验一遍看有没有 bug
- 你反馈问题我修, 无问题再进下一项
