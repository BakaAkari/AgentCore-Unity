## Bug 1: `batch_execute` 输出截断到 500 chars

### 现象

在 Windows 侧真实测试 `batch_execute` 包 `manage_physics` 的 `list_scene_physics_stats` + `get_collision_matrix` 时:
- 第一个子 tool 输出完整 (~800 chars)
- **第二个子 tool 输出被截断为 `...(truncated)`** — 后半段的 `ignored_pairs` 数组等大字段丢失
- LLM 拿到截断结果后, 用消息里的 summary text 做 **plausible reconstruction** 输出 "完整 JSON" — 但那是推断不是真实数据, 违反 SOUL §1 (honesty over plausibility)

### 根因

`Editor/Tools/Native/Meta/BatchExecuteTool.cs`:

- **Line 219**: `["output"] = TruncateOutput(result.Output, 500)`
- **Line 322-327**: `TruncateOutput(string, int)` 硬编码 `maxLength=500`

500 chars 是 v1.7.x batch_execute 立项时的保守值, v1.10.0 加了很多返回结构化大 JSON 的工具后没跟着调.

### 修法

**Step B1.1**: 提出常量, 参数化 max length

```csharp
// BatchExecuteTool.cs class body 顶部

/// <summary>Default max chars per sub-tool output before truncation (from 500 in v1.10.0, raised in v1.10.1).</summary>
private const int DefaultMaxOutputChars = 8000;

/// <summary>Hard upper bound to prevent runaway context bloat, even when caller passes a huge number.</summary>
private const int MaxAllowedOutputChars = 50000;
```

**Step B1.2**: Schema 加参数 `max_output_chars_per_op`

在 `_parametersSchema` 的 `properties` 里加:

```json
"max_output_chars_per_op": {
    "type": "integer",
    "description": "Max chars per sub-tool output before truncation. Default 8000 (v1.10.1). Set to -1 to disable truncation (bounded by 50000 hard cap). Use higher values when sub-tool outputs are structured JSON (collision matrices, assembly lists, physics stats)."
}
```

**Step B1.3**: `ExecuteAsync` 里读参数 (在 `stopOnError`/`transaction` 后)

```csharp
var maxOutputChars = ToolHelpers.GetOptionalInt(parameters, "max_output_chars_per_op", DefaultMaxOutputChars);
if (maxOutputChars < 0) maxOutputChars = MaxAllowedOutputChars;
if (maxOutputChars > MaxAllowedOutputChars) maxOutputChars = MaxAllowedOutputChars;
```

**Step B1.4**: Line 219 的调用改成

```csharp
["output"] = TruncateOutput(result.Output, maxOutputChars)
```

**Step B1.5**: `TruncateOutput` 方法改成明确 hint

```csharp
/// <summary>
/// Truncate output string to avoid oversized responses.
/// When truncation happens, appends an explicit hint so the LLM knows to call the tool directly if it needs the full output.
/// </summary>
private static string TruncateOutput(string output, int maxLength)
{
    if (string.IsNullOrEmpty(output)) return output;
    if (output.Length <= maxLength) return output;
    var omitted = output.Length - maxLength;
    return output.Substring(0, maxLength) +
        $"\n...(truncated by batch_execute: {omitted} chars omitted. " +
        $"Call this tool directly outside batch_execute, or increase max_output_chars_per_op to see full output.)";
}
```

### 验证

- 编译通过
- 手工 smoke: batch_execute 包 get_collision_matrix — 8000 chars 应该覆盖 3d matrix 完整输出

## Bug 2: Windows 路径分隔符未 normalize (跨平台一致性)

### 现象

在 Windows 侧真实测试:

- ✅ `manage_editor.get_selection` → `scene_path: "Assets/Scenes/Main.unity"` (正斜杠)
- ✅ `manage_file.read` → `path: "Packages/com.agentcore.unity/package.json"` (正斜杠)
- ❌ `manage_memory_profiler.list_memory_snapshots` → `folder: "D:\\Unity Project\\Agent Core Test Project\\Megacity Metro\\MemoryCaptures"` (**反斜杠**)

同一份 JSON 数据在 macOS 上 folder 用 `/`, 在 Windows 用 `\`, 语义不同. 结构性问题不只 memory_profiler 一家 — 全项目 audit 发现:

- **6 处独立的手动 `Replace("\\", "/")`** 散在 CleanerTool / ManageScriptTool / LightRAGTool / ManageAnimationTool — normalize 逻辑没有统一 helper
- **`ManageFileTool.ToRelativePath` (line 276-284)** — 已正确 normalize, 是标杆但不共享

### Audit 结果 (bug 位置)

**需要 normalize 的具体行 (变量来源都是 `Path.Combine` / `FileInfo.FullName` / `DirectoryInfo.FullName`, 在 Windows 上是反斜杠)**:

1. **`Editor/Tools/Native/Extended/ManageMemoryProfilerTool.cs`**:
   - Line 91 (`GetProjectRoot` — 内部工具方法, 用于后续拼接)
   - Line 115 (`GetDefaultSnapshotFolder`)
   - Line 180 (`["path"] = finalPath ?? path` in `HandleTakeAsync`)
   - Line 272 (`["folder"] = folder` in `HandleList`)
   - Line 284 (`["path"] = fi.FullName` in `HandleList` snapshots 数组元素)
   - Line 312 (`["path"] = path` in `HandleAnalyze`)
   - Line 363-364 (`["path_a"] = pathA` / `["path_b"] = pathB` in `HandleDiff`)

2. **`Editor/Tools/Native/Bootstrap/ManageWorkspaceConfigTool.cs`**:
   - `filePath` 来自 `BootstrapLoader.GetDefaultUserFilePath` → `Path.Combine(projectRoot, "AgentCore", fileName)` + `projectRoot = Directory.GetParent(...).FullName` → Windows 反斜杠
   - Line 140 (`["path"] = filePath` in HandleReadFile response)
   - Line 171 (`["path"] = filePath` in HandleWriteFile response)
   - Line 186 (`var projectRoot = Directory.GetParent(...).FullName` in `HandleGetLocations` — 也有输出 path)

**天生正确 (不需要改, 已核实来源)**:
- `scene.path` / `activeScene.path` — Unity 内部 asset path
- `AssetDatabase.GetAssetPath(...)` — Unity 内部 asset path

- 直接回传用户输入的 `path` 参数 (ManageScriptTool / ManagePrefabTool / ManageScriptableObjectTool 等) — 用户传什么显什么
- `ManageAssetTool` 的 `fullPath` — 由 `parentFolder/folderName` 拼接的 Unity asset path, 已是 `/`

**已正确 normalize (可迁移到 helper 消除重复, 非阻塞)**:
- `ManageFileTool.ToRelativePath` line 276-284 (标杆实现)
- `CleanerTool` line 291, 462, 489, 531 (4 处手动 Replace)
- `ManageScriptTool` line 349, 763 (2 处手动 Replace)
- `LightRAGTool` line 287-290, 460-463, 565 (6 处手动 Replace)
- `ManageAnimationTool` line 683 (1 处手动 Replace)
- `ToolHelpers.NormalizeAssetPath` line 406 (asset path 用, 语义不同, 保留)

### 修法

**Step B2.1**: 新建 `Editor/Tools/Infrastructure/PathUtils.cs`

```csharp
using System;
using System.IO;
using UnityEngine;

namespace AgentCore.Editor.Tools.Infrastructure
{
    /// <summary>
    /// Filesystem path helpers for tool return values.
    ///
    /// **CRITICAL RULE**: All tool JSON responses exposing a file/folder path
    /// MUST route the string through <see cref="ToUnityPath"/> to guarantee
    /// cross-platform consistency. Windows native APIs (Path.Combine, FileInfo.FullName,
    /// Directory.GetCurrentDirectory) return backslashes; Unity conventions use
    /// forward slashes. Direct assignment breaks cross-platform data consistency
    /// (a JSON payload readable on macOS becomes semantically different on Windows).
    ///
    /// See SOUL.md §2.14 "File Path Return Values".
    /// </summary>
    public static class PathUtils
    {
        /// <summary>
        /// Normalize any filesystem path to Unity-style forward slashes.
        /// Idempotent. Returns input unchanged if null/empty.
        /// </summary>
        public static string ToUnityPath(string path)
        {
            if (string.IsNullOrEmpty(path)) return path;
            return path.Replace('\\', '/');
        }

        /// <summary>
        /// Absolute project root (parent of Assets), normalized to forward slashes.
        /// Trailing slash removed.
        /// </summary>
        public static string ProjectRoot
        {
            get
            {
                var raw = Path.GetFullPath(Path.Combine(Application.dataPath, ".."));
                return ToUnityPath(raw).TrimEnd('/');
            }
        }

        /// <summary>
        /// Make an absolute path relative to project root, or return normalized absolute
        /// path if the input lies outside the project. Always uses forward slashes.
        /// </summary>
        public static string ToProjectRelative(string absolutePath)
        {
            if (string.IsNullOrEmpty(absolutePath)) return absolutePath;
            var normalized = ToUnityPath(absolutePath);
            var root = ProjectRoot;
            if (normalized.StartsWith(root, StringComparison.OrdinalIgnoreCase))
            {
                var relative = normalized.Substring(root.Length);
                return relative.TrimStart('/');
            }
            return normalized;
        }
    }
}
```

**Step B2.4**: 加 SOUL 规则

在 `Editor/Bootstrap/Resources/SOUL.md` §2 (Operating Discipline) 末尾追加子规则 §2.14:

```markdown
### §2.14 File Path Return Values (Cross-Platform Consistency)

Any tool exposing a filesystem path/folder/directory in its JSON response
MUST route the string through `AgentCore.Editor.Tools.Infrastructure.PathUtils.ToUnityPath()`
before assignment. Windows native APIs (`Path.Combine`, `FileInfo.FullName`,
`DirectoryInfo.FullName`, `Directory.GetCurrentDirectory()`) return backslashes;
Unity conventions use forward slashes. Direct assignment produces JSON payloads
whose semantics differ between Windows and macOS/Linux clients.

**Exempt** (already forward-slash by Unity API contract):
- `scene.path` / `activeScene.path` / any `AssetDatabase.GetAssetPath(...)` result
- `GetGameObjectPath()` (hierarchy path, not filesystem)
- Verbatim user-supplied `path` parameters echoed back
- Values already routed through `ToolHelpers.NormalizeAssetPath` or
  `PathUtils.ToProjectRelative`
```

**Step B2.5** (非阻塞, 可选): 迁移已有手动 `Replace("\\", "/")` 到 `PathUtils.ToUnityPath` 消除重复.
本 patch **不做**这个 — 保持修改集聚焦. 拉到 v1.10.2 或以后.
